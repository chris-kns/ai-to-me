# Candidaturas: o loop

> Candidatura não é um evento no fim do plano. É um **loop**: ajusta currículo → candidata → entrevista → recebe feedback → estuda → candidata de novo. Quanto antes começar o loop, mais rápido aprende.

## Acompanhamento

| Data | Empresa | Vaga | Canal | Status | Próximo passo | Feedback / aprendizado |
|------|---------|------|-------|--------|---------------|-------------------------|
|  |  |  |  | enviada / triagem / entrevista / teste / oferta / recusa |  |  |
|  |  |  |  |  |  |  |
|  |  |  |  |  |  |  |

## Depois de cada entrevista (10 min, no mesmo dia)

- O que me perguntaram que eu não soube responder? → registre em [pontos-fracos.md](../flashcards/pontos-fracos.md)
- O que respondi bem? (repita)
- Que decisão do meu projeto eu não consegui defender?
- O que mudo no currículo ou no README?

## Checklist antes de candidatar

- [ ] Currículo com a narrativa "infraestrutura → plataforma/backend"
- [ ] LinkedIn alinhado ao currículo
- [ ] Repositórios com README (problema, regras, como rodar, decisões)
- [ ] CI verde e instruções de execução testadas do zero
- [ ] Perfil do GitHub com README de apresentação
